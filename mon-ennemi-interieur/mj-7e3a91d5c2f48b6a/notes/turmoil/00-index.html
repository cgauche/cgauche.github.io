## Schéma commun à toutes les fiches (10 sections, ordre exact)

1. **Identité du front** — provinces concernées, symboles politiques (Croc, titre, capitale, culte), acteurs principaux avec liens `PNJ`
2. **État pré-Turmoil** (Spring 2512 IC) — gouvernance, alliances, tensions, religion, statut impérial
3. **Déclencheur(s) canon** — événements précis qui basculent le front + acteurs Main Pourpre le cas échéant
4. **Chronologie détaillée** — **tableau à 4 colonnes** : `Date IC` \| `Repère narratif EiR` \| `Événement` \| `Source ligne`. *Date IC = "—" si canon ne la donne pas. Repère narratif = chapitre EiR + session table équivalente si pertinent.*
5. **État post-Turmoil canon** — symétrique de section 2
6. **Acteurs — pré → post** — tableau `Acteur` \| `Pré-Turmoil` \| `Post-Turmoil` \| `Statut canon`
7. **Cascades vers d'autres fronts** — liens `Turmoil/0X - Nom complet`
8. **Hooks jouables** — **canon + extensions logiques évidentes**. Chaque hook balisé `(canon)` ou `(canon + déduction)` + position narrative (background / actif / résolution) + source
9. **Sources canon (lignes précises)** — toutes les références + URLs web consultées
10. **Ambiguïtés canon** — questions non tranchées par les livres ; pour chaque ambiguïté, indiquer le **poids relatif** des sources contradictoires selon hiérarchie **EiR > Companion > Archives > supplément > web**. Pas une décision GM, juste l'aide à trancher.

## Standard de rigueur

- **Pur canon C7.** Aucune extrapolation, aucune invention. Si non tranché → section 10 explicitement.
- **Aucun "probablement" non documenté.** Soit sourcé, soit en section 10.
- **Références de lignes précises** systématiquement (pas de "vers le début du chapitre").
- **Recoupement Fandom/Lexicanum obligatoire** pour chaque front, sur chaque PNJ majeur + province + Croc Runique.
- **Aucune référence aux divergences table** (canon pur uniquement — les variations Gauche sont traitées ailleurs).
- **Volume** : pas de plafond, exhaustivité maximale.

## Filtre section 10 — Ambiguïtés canon (règle stricte)

Section 10 contient **uniquement** les questions où :
1. Le canon C7 (EiR + Companion + Archives + supplements) **ne tranche pas**, ET
2. **Le web (Fandom + Lexicanum + supplements indirects) ne tranche pas non plus** après recherche ciblée systématique sur chaque ambiguïté suspectée, ET
3. La question n'est **pas couverte par CLAUDE.md** (orthographes, conventions de nommage), ET
4. La question n'est **pas une variable PJ** (canon dit "selon les actions des Characters"), ET
5. La question n'est **pas une rumeur in-monde** (la rumeur EST canon, pas la "vraie réponse"), ET
6. La question n'est **pas un fait technique** déjà documenté ailleurs (règles de combat, mécaniques de jeu, etc.).

**Workflow** :
- Pour chaque ambiguïté suspectée, lancer un WebSearch ciblé avant de la déclarer "ambiguïté canon".
- Si web tranche → l'ambiguïté n'existe pas, intégrer la réponse en section 5/6/9 (avec citation web).
- Si web ne tranche pas → garder en section 10 avec mention explicite "web ne tranche pas non plus".

**Anti-pattern à ne pas reproduire** (vu sur fiche 01 v1 → corrigée v2) : flagger 11 ambiguïtés dont 9 étaient résolubles par CLAUDE.md, web direct, ou analyse interne. La règle est stricte.

## Web cross-check obligatoire — pour rédacteur ET pour audit

### Pour la rédaction de fiche (Phase 2)
Avant de finaliser une fiche, **WebSearch ciblé obligatoire** sur :
- Chaque PNJ majeur (Fandom + Lexicanum)
- Chaque Croc Runique mentionné
- Chaque province / cité concernée
- Chaque date dynastique citée (pour vérifier régressions type Hjalmar -300 ans)
- Chaque orthographe nominale suspecte (CLAUDE.md règle "Lexicanum/Fandom > PDF OCR")

### Pour l'audit externe (Phase 5)
**Brief obligatoire à inclure dans chaque dispatch d'agent auditeur** :

> **Web cross-check OBLIGATOIRE (preuve documentée).** Pour chaque assertion canon centrale critiquée dans ton rapport, tu DOIS effectuer un WebSearch ciblé sur Fandom + Lexicanum + Cubicle 7 blog, et CITER les URLs dans la critique. Si tu n'as pas web-vérifié une assertion, écris explicitement "non-vérifié web" — ne propage pas un verdict canon sans web cross-check quand l'inconsistance est inter-source. **Minimum requis : 5 WebSearch documentés (URLs incluses)**. Une critique sans bloc "Web cross-check effectués" listant les URLs sera considérée comme incomplète.

**Anti-pattern observé** (audits fiche 02 v1 + v2) : verdict du critique appuyé uniquement sur Source/ vérifications, sans recoupement web. Conséquence : ambiguïtés flaguées qui auraient pu être tranchées par Fandom (ex : orthographe Holswig-Abenhauer, généalogie Bildhofen-Magnus), erreurs orthographe non flaguées par CLAUDE.md memo, etc.

**Règle stricte** : un audit qui ne documente aucun WebSearch n'est pas un audit valide selon le standard de ce dossier.

## Workflow d'une fiche (6 phases)

1. **Cadrage** — identifier provinces, acteurs, symboles, sources à consulter, questions ouvertes.
2. **Lecture canon** dans l'ordre fixe : (a) EiR ch.17 → (b) EiR Intro → (c) EiR ch.5-13 ciblés → (d) EiR Companion ch.X dédié → (e) Archives Vol I → (f) Supplements dédiés → (g) PBT / antécédents si pertinent.
3. **Web cross-check** — Fandom + Lexicanum pour chaque PNJ majeur + province + Croc ; élargissement (worldanvil, etc.) si zone d'ombre persiste.
4. **Rédaction** section par section selon schéma.
5. **Quality gates** — vérifier : tout fait corps → source en section 9 ; "probablement" → section 10 ; contradictions → section 10 avec poids relatif.
6. **Self-review** — liens, cohérence interne, schéma 1-10 respecté.

## Anti-pattern : propagation incomplète après spot-fixes (leçon fiche 05)

**Observé fiche 05 v2 → v3** : audit v1 a flaggé 3 critiques canon (Hans-Hals I→III, Luddataal Chosen→Shield, Bergsburg→Hergig). Les spot-fixes ont corrigé section 1 + tableau acteurs + Notes hors filtre, **mais 7+ occurrences résiduelles** sont restées dans Alliances, Déclencheurs, Chronologie section 4, Cascade vers fiche 06, et Notes hors filtre WFRP4/WFRP2 — créant une incohérence interne immédiatement visible que l'audit v2 a détectée (note 7.6 → 8.4 → 8.8 seulement après propagation complète).

**Cause** : un changement de nom propre canon (Hans-Hals **I** → **III**, capitale **Bergsburg** → **Hergig**, etc.) **se propage partout dans la fiche** — pas seulement aux endroits explicitement flaggés par l'audit.

**Règle Phase 6 (Spot-fixes)** :
- **AVANT** de marquer la fiche comme "produite" post-spot-fixes : exécuter un **Grep de propagation** sur chaque token corrigé.
- Exemple concret fiche 05 : après correction "Hans-Hals I → III" en section 1, faire `Grep "Hans-Hals I[^I]"` sur la fiche entière → liste exhaustive des occurrences résiduelles → corriger une par une.
- Idem pour orthographes (Bergsburg/Hergig, Pfeifraucher/Pfeiffraucher, Söll/Soll, Geschberg/Geschburg, etc.).
- Idem pour titres/traductions canonisées (Luddataal "Shield of Taal" ≠ "Chosen of Taal").

**Vérification structurée** : un Grep avant publication couvre les corps de texte ET les tableaux ET les Notes hors filtre — l'audit auditif d'un agent ne couvre qu'une partie. Le Grep est la garantie objective.
